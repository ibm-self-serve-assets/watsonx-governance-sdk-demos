PROMPT 1.1: Intent Interpretation
----------------------------------
Location: supervisory_agent.py, line 152
Purpose: Analyze seller query to extract intent, partner name, and workflow type
Model: meta-llama/llama-3-3-70b-instruct
Parameters:
  - max_new_tokens: 300
  - temperature: 0.1
  - decoding_method: greedy

Template:
```
You are a sales workflow assistant. Analyze this seller query and extract:

Query: {query}

Provide in this exact format:
INTENT: [What the seller wants to do]
PARTNER_NAME: [Name of partner/company mentioned, or 'Unknown']
WORKFLOW_TYPE: [contract_analysis/next_action/general_inquiry]
CONTRACT_MENTIONED: [yes/no]
KEY_ENTITIES: [Any other important entities mentioned]
```

Input Variables:
  - query: The seller's natural language query

Output Format:
  - Structured text with labeled fields
  - Used to determine which agents to invoke

Example Input:
  "I'm a new seller at IBM. I recently got Confluent as a new customer..."

Example Output:
  INTENT: Understand contract renewal and expiration status for Confluent
  PARTNER_NAME: Confluent
  WORKFLOW_TYPE: contract_analysis
  CONTRACT_MENTIONED: yes
  KEY_ENTITIES: IBM, CRM, Contracts, webscraped information

PROMPT 2.1: Contract Metadata Extraction
-----------------------------------------
Location: contract_agent.py, line 277
Purpose: Extract key metadata from contract text
Model: meta-llama/llama-3-3-70b-instruct
Parameters:
  - max_new_tokens: 500
  - decoding_method: greedy

Template:
```
You are a contract analysis expert. Extract key metadata from this contract:

{contract_text}

Extract and provide in this exact format:
PARTIES: [List all parties involved]
EFFECTIVE_DATE: [Contract effective date]
TERM_LENGTH: [Duration/term of contract]
KEY_OBLIGATIONS: [Main obligations and responsibilities]
MILESTONES: [Key milestones or deliverables]

If information is not found, write 'Not specified'.
```

Input Variables:
  - contract_text: First 3000 characters of contract document

Output Format:
  - Structured text with labeled fields
  - Each field on separate line

Example Input:
  "This Agreement is entered into on January 30, 2024 between IBM Corporation..."

Example Output:
  PARTIES: IBM Corporation, Confluent Inc.
  EFFECTIVE_DATE: January 30, 2024
  TERM_LENGTH: 2 years
  KEY_OBLIGATIONS: Software licensing, support services, data processing
  MILESTONES: Q1 2024 implementation, Q2 2024 go-live

PROMPT 2.2: Contract Metadata Normalization
--------------------------------------------
Location: contract_agent.py, line 359
Purpose: Convert extracted metadata into structured JSON format with business fields
Model: meta-llama/llama-3-3-70b-instruct
Parameters:
  - max_new_tokens: 400
  - decoding_method: greedy

Template:
```
Based on this extracted contract metadata and text:

{metadata}

Contract Text (first 5000 chars):
{contract_text}

Create a structured JSON summary with these fields:
- amount: total contract value with currency (e.g., '$500,092.80')
- products: array of specific products/services mentioned (e.g., ['watsonx as a Service', 'watsonx Orchestrate'])
- start_date: contract start date (YYYY-MM-DD format if possible)
- end_date: contract end/expiration date (YYYY-MM-DD format if possible)
- term_length: normalized duration (e.g., '1 year', '2 years')
- parties: array of party names
- contract_type: inferred type (e.g., 'ESA', 'MSA', 'Sales Agreement')

Extract these from the contract text using context clues. For dates, look for:
- "Effective Date", "Start Date", "Commencement Date"
- "Expiration Date", "End Date", "Term End"
- "for a period of X years"

Provide ONLY valid JSON, no additional text.
```

Input Variables:
  - metadata: Raw extracted metadata from PROMPT 2.1
  - contract_text: First 5000 characters for better context

Output Format:
  - Valid JSON object
  - No markdown formatting or explanations

Example Input:
  PARTIES: IBM Corporation, Confluent Inc.
  EFFECTIVE_DATE: January 30, 2025
  TERM_LENGTH: 1 year(s) from effective date
  Contract Text: "...total amount of $500,092.80...watsonx as a Service..."

Example Output:
  {
    "amount": "$500,092.80",
    "products": ["watsonx as a Service", "watsonx Orchestrate"],
    "start_date": "2025-01-30",
    "end_date": "2026-01-30",
    "term_length": "1 year(s)",
    "parties": ["IBM Corporation", "Confluent Inc."],
    "contract_type": "ESA"
  }

--------------------------------------
Location: research_agent.py, line 388
Purpose: Synthesize internal CRM data and external research into partner profile
Model: meta-llama/llama-3-3-70b-instruct
Parameters:

```
You are a sales intelligence analyst. Synthesize the internal sales data and external research into a comprehensive partner profile.

1. Partner maturity level and engagement history
2. Historical sales velocity and deal patterns
3. Prior deal blockers and how to address them
```

PROMPT 4.1: LLM-Based Contract-CRM Matching (ENHANCED)
-------------------------------------------------------
Location: matching_agent.py, line 159
Purpose: Intelligently match contracts to CRM opportunities using semantic understanding, with enhanced renewal detection and CRM stage analysis
Model: meta-llama/llama-3-3-70b-instruct
Parameters:
  - max_new_tokens: 500
  - temperature: 0.1
  - decoding_method: greedy

Template:
```
You are a contract-CRM matching expert. Analyze this contract and determine which CRM opportunities (if any) are related to it.

CONTRACT INFORMATION:
{contract_info}

CRM OPPORTUNITIES:
{opp_info}

MATCHING CRITERIA:
1. Product/service alignment (e.g., "watsonx ESA" matches "watsonx as a Service", "Cognos" matches "Cognos Analytics")
2. Dollar amount proximity (within reasonable range)
3. Timeline alignment (contract dates vs opportunity close dates)
4. Semantic relationships (understand product families and variations)

Provide your analysis in this EXACT format:

MATCHED_OPPORTUNITIES: [comma-separated list of opportunity numbers that match, or "NONE"]
CONFIDENCE: [high/medium/low]
REASONING: [Brief explanation of why these opportunities match or don't match]

Be thorough - consider semantic relationships, not just exact string matches.
```

ENHANCEMENTS IN VERSION 4.0:
- Automatic calculation of days_until_renewal for every contract
- Renewal urgency classification (EXPIRED, CRITICAL, HIGH, MEDIUM, LOW)
- Detection of renewal contracts from titles ("renewal" in filename)
- CRM stage analysis: Lost = FAILED, Won = CONTRACT SIGNED, Other = ACTIVE ENGAGEMENT
- Active engagement flag to identify contracts being actively worked
- Urgent alerts for contracts without CRM tracking
- Enhanced output with visual indicators (emojis) and sorted by urgency

Input Variables:
  - contract_info: Contract file name, products, amount, dates, status
  - opp_info: List of CRM opportunities with names, owners, products, amounts, stages, next steps

Output Format:
  - MATCHED_OPPORTUNITIES: List of opportunity indices (1-based) or "NONE"
  - CONFIDENCE: high/medium/low
  - REASONING: Explanation of matching logic

Example Input:
  CONTRACT INFORMATION:
  Contract File: Confluent_IBM-1.30.2025.docx
  Products: watsonx ESA
  Amount: $250,000
  Start Date: 1/31/2024
  End Date: 1/31/2026
  Status: expired
  
  CRM OPPORTUNITIES:
  Opportunity 1:
  Name: Confluent watsonx as a Service Renewal
  Owner: Anand Das
  Products: watsonx
  Amount: $250,000
  Stage: Qualified
  Next Steps: sizing in progress

Example Output:
  MATCHED_OPPORTUNITIES: 1
  CONFIDENCE: high
  REASONING: "watsonx ESA" is semantically equivalent to "watsonx as a Service". Dollar amounts match exactly ($250K). Timeline supports renewal scenario (contract expired, opportunity in qualified stage). Strong match on all criteria.

Fallback Behavior:
  - If LLM fails, system falls back to simple string matching
  - Fallback uses substring matching on product names
  - Fallback provides lower confidence scores

The Matching Agent returns enriched match objects containing:
  - Complete contract object with all structured fields (amount, products, dates)
  - Complete CRM opportunity details (owner, next_steps, stage, amount)
  - Match confidence level (high/medium/low)
  - Match reasoning (LLM explanation)
  - Status and urgency metrics

PROMPT 5.1: Draft Email Generation (ENHANCED)
----------------------------------------------
Location: action_agent.py, line 804
Purpose: Generate professional executive outreach email with contract context, expansion opportunities, and previous signers
Model: meta-llama/llama-3-3-70b-instruct
Parameters:
  - max_new_tokens: 600
  - temperature: 0.3
  - decoding_method: sample

Template:
```
Write a professional, executive-level outreach email from an IBM seller to {recipient_display} at {partner_name}.

RECIPIENT INFORMATION:
- Role: {recipient_role}
- Name: {recipient_name}
- Use name in greeting if provided, otherwise use role title
- NOTE: For Confluent CPO, name is ALWAYS "Shaun Clowes" (pre-acquisition executive)

CONTRACT CONTEXT:
{contract_details}

CRM INFORMATION:
{crm_context}

URGENCY:
{urgency_context}

EXPANSION OPPORTUNITIES:
{expansion_analysis}

PREVIOUS SIGNERS:
{previous_signers}

ADDITIONAL CONTEXT:
- Risk Level: {risk_level}
- Partner Maturity: {maturity}
- Top Priority Action: {top_step}
- Why Contract Expired: {expiration_reason}

EMAIL REQUIREMENTS:
1. Use executive tone appropriate for {recipient_role} level
2. Reference specific contract details (product, value, dates) naturally
3. Acknowledge CRM status and next steps if available
4. Convey urgency without being alarmist
5. Include clear call to action with specific meeting request
6. Keep it concise (under 200 words)
7. Avoid legal jargon and operational details
8. If name is provided, use it in greeting (e.g., 'Dear [Name]'), otherwise use role (e.g., 'Dear Chief Procurement Officer')
9. Mention expansion opportunities if identified
10. Reference previous signers if appropriate for continuity
11. MUST end with EXACTLY this signature (no variations):
    Best regards,
    [Your Name]
    IBM Seller

Return ONLY the final email draft. Do NOT include:
- Multiple versions or drafts
- Editing notes or suggestions
- Meta-commentary or explanations
- Alternative phrasings

Provide ONE complete, polished email ready to send.
```

ENHANCEMENTS IN VERSION 4.0:
- Hard-coded Confluent CPO: Shaun Clowes (pre-acquisition)
- Expansion opportunity context included in email
- Previous contract signers referenced for continuity
- Root cause analysis of why contract expired
- Enhanced context for more targeted outreach

Input Variables:
  - recipient_display: Name or role of recipient (e.g., "John Smith" or "CPO")
  - recipient_role: Executive role (CPO, CTO, CEO)
  - recipient_name: Actual name if available, otherwise "Not available - use role title"
  - partner_name: Company name (e.g., "Confluent")
  - contract_details: Specific contract information (product, value, dates, status)
  - crm_context: CRM opportunity details (owner, next steps, stage)
  - urgency_context: Urgency explanation (days expired, risk factors)
  - risk_level: High/Medium/Low
  - maturity: Partner maturity level (Strategic Partner, Engaged Prospect, etc.)
  - top_step: Top priority action from recommendations

Output Format:
  - Complete email with subject line
  - Professional greeting (uses name if available)
  - 2-3 paragraph body
  - Clear call to action
  - Professional closing: "Best regards, [Your Name], IBM Seller"

Example Input:
  recipient_display: John Smith
  recipient_role: CPO
  recipient_name: John Smith
  partner_name: Confluent
  contract_details: watsonx ESA contract ($500,092.80) expired 68 days ago on 1/31/2026
  crm_context: Anand Das owns renewal opportunity, next steps: "sizing in progress"
  urgency_context: Contract expired 68 days ago, $500K at risk, customer actively sizing
  risk_level: High
  maturity: Strategic Partner
  top_step: Contact Anand Das TODAY to finalize sizing

Example Output:
  Subject: Confluent watsonx ESA Partnership - Renewal Discussion

  Dear John Smith,

  I hope this message finds you well. I'm reaching out regarding our watsonx ESA partnership agreement, which concluded on January 31st. I understand from our team that Confluent is actively working through sizing requirements for renewal, which is excellent news.

  Given the strategic value of this $500,000 partnership and your ongoing evaluation, I'd like to schedule a brief call this week to ensure we're aligned on your requirements and timeline. Our team is ready to support your sizing process and expedite the renewal to maintain continuity.

  Would you be available for a 30-minute discussion this Thursday or Friday? I'm happy to work around your schedule.

  Best regards,
  [Your Name]
  IBM Seller

PROMPT MODIFICATION GUIDELINES

When modifying prompts:

1. Maintain Structure: Keep the input/output format consistent
2. Test Thoroughly: Verify changes with multiple test cases
3. Document Changes: Update this guide when prompts are modified
4. Version Control: Track prompt versions for rollback if needed
5. Monitor Quality: Check output quality after prompt changes
6. Add Context: Include more context in prompts for better extraction
7. Be Explicit: Specify exact requirements (e.g., "MUST end with...")
8. Post-Process: Add code-level post-processing for reliability

PROMPT ENGINEERING BEST PRACTICES

1. Be Specific: Clearly define expected output format
2. Provide Examples: Include example inputs/outputs when helpful
3. Set Constraints: Specify length limits, tone, and style requirements
4. Use Delimiters: Separate sections with clear markers
5. Avoid Ambiguity: Use precise language and explicit instructions
6. Test Edge Cases: Verify behavior with unusual inputs
7. Iterate: Refine prompts based on actual output quality
8. Add Context: More context = better extraction (e.g., include contract text)
9. Enforce Format: Use "MUST", "EXACTLY", "ONLY" for critical requirements
10. Combine Approaches: Use prompts + post-processing for reliability

================================================================================

TROUBLESHOOTING

Common Issues and Solutions:

Issue: LLM returns explanations instead of just the output
Solution: Add "Return ONLY [desired output], no additional text" to prompt

Issue: Output format is inconsistent
Solution: Provide explicit format template with examples

Issue: LLM ignores specific instructions
Solution: Emphasize critical requirements with "IMPORTANT:", "MUST:", or "EXACTLY:"

Issue: Output is too verbose
Solution: Add length constraints (e.g., "Keep it concise (under 200 words)")

Issue: Tone is inappropriate
Solution: Specify exact tone (e.g., "Use executive tone appropriate for CPO level")

Issue: LLM generates multiple versions
Solution: Add "Do NOT include multiple versions" + post-processing to extract first only

Issue: Missing specific data (amount, products, dates)
Solution: Include more context in prompt (e.g., contract text, not just metadata)

Issue: Generic recipients instead of names
Solution: Enhance research to extract executive names, pass to email prompt

Issue: Inconsistent field names in output
Solution: Use consistent naming across all agents (e.g., "next_steps" not "agent_next_steps")

================================================================================

PERFORMANCE OPTIMIZATION

Tips for faster, more reliable prompts:

1. Cache Results: Store extracted data to avoid re-processing (contracts_cache.json)
2. Reduce Token Count: Use concise prompts without unnecessary words
3. Greedy Decoding: Use for structured outputs (metadata, JSON)
4. Sample Decoding: Use for creative outputs (emails, summaries)
5. Lower Temperature: Use 0.1-0.3 for factual extraction
6. Higher Temperature: Use 0.5-0.7 for creative writing
7. Batch Processing: Process multiple items in one call when possible
8. Rule-Based First: Use code for simple tasks (matching), LLM for complex (synthesis)
