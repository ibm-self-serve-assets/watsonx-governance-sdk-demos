PROMPT 2.2: Contract Metadata Normalization
--------------------------------------------
Location: contract_agent.py, line 359
Purpose: Convert extracted metadata into structured JSON format with business fields
Model: meta-llama/llama-3-3-70b-instruct
Parameters:
  - max_new_tokens: 400
  - decoding_method: greedy

Template:
```
Based on this extracted contract metadata and text:

{metadata}

Contract Text (first 5000 chars):
{contract_text}

Create a structured JSON summary with these fields:
- amount: total contract value with currency (e.g., '$500,092.80')
- products: array of specific products/services mentioned (e.g., ['watsonx Orchestrate', 'watsonx.governance', 'watsonx.ai'])
- start_date: contract start date (YYYY-MM-DD format if possible)
- end_date: contract end/expiration date (YYYY-MM-DD format if possible)
- term_length: normalized duration (e.g., '1 year', '2 years')
- parties: array of party names
- contract_type: inferred type (e.g., 'ESA', 'MSA', 'Sales Agreement')

Extract these from the contract text using context clues. For dates, look for:
- "Effective Date", "Start Date", "Commencement Date"
- "Expiration Date", "End Date", "Term End"
- "Coverage Period" in tables (format: MM/DD/YYYY-MM/DD/YYYY)
- "for a period of X years"

For products, look in "IBM Cloud Subscription" table under "Product Description":
- If "IBM watsonx as a Service" appears: extract ["watsonx Orchestrate", "watsonx.governance", "watsonx.ai"]
- Also check for "Cognos"

Provide ONLY valid JSON, no additional text.
```

Input Variables:
  - metadata: Raw extracted metadata from PROMPT 2.1
  - contract_text: First 5000 characters for better context

Output Format:
  - Valid JSON object
  - No markdown formatting or explanations

Example Input:
  PARTIES: IBM Corporation, Confluent Inc.
  EFFECTIVE_DATE: January 30, 2025
  TERM_LENGTH: 1 year(s) from effective date
  Contract Text: "...total amount of $250,000.00...Coverage Period: 01/31/2024-01/31/2026...IBM watsonx as a Service..."

Example Output:
  {
    "amount": "$250,000.00",
    "products": ["watsonx Orchestrate", "watsonx.governance", "watsonx.ai"],
    "start_date": "2024-01-31",
    "end_date": "2026-01-31",
    "term_length": "2 year(s)",
    "parties": ["IBM Corporation", "Confluent Inc."],
    "contract_type": "ESA"
  }

CRITICAL IMPLEMENTATION NOTES:
- Date extraction uses regex to parse Coverage Period field: (\d{2}/\d{2}/\d{4})-(\d{2}/\d{2}/\d{4})
- Second date in Coverage Period is the end_date (expiration date)
- DO NOT calculate end_date as start_date + term_length
- Product extraction looks at IBM Cloud Subscription table's Product Description column
- If "IBM watsonx as a Service" found: extract all three watsonx products
- Also check for "Cognos" in product description

PROMPT 4.1: LLM-Based Contract-CRM Matching (ENHANCED)
-------------------------------------------------------
Location: matching_agent.py, line 133
Purpose: Intelligently match contracts to CRM opportunities using semantic understanding, with enhanced renewal detection and CRM stage analysis
Model: meta-llama/llama-3-3-70b-instruct
Parameters:
  - max_new_tokens: 500
  - temperature: 0.1
  - decoding_method: greedy

Template:
```
You are a contract-CRM matching expert. Analyze this contract and determine which CRM opportunities (if any) are related to it.

CONTRACT INFORMATION:
{contract_info}

CRM OPPORTUNITIES:
{opp_info}

MATCHING CRITERIA:
1. For EXPIRED contracts: Look for ACTIVE opportunities (Stage=Qualify/Design/Engage/Negotiate) with:
   - Same/similar products (semantic understanding: "watsonx ESA" = "watsonx as a Service")
   - Similar dollar amounts (within 7% tolerance for expired contracts)
   - Next Steps mentioning "renewal", "expired", or "renew"
   - Contract Expiration Date in CRM matching the expired contract date

2. For ACTIVE contracts: Standard matching on:
   - Product/service alignment (e.g., "Cognos" matches "Cognos Analytics")
   - Dollar amount proximity (within reasonable range)
   - Timeline alignment (contract dates vs opportunity close dates)
   - Semantic relationships (understand product families)

3. Use Contract Expiration Date from CRM for better context

Provide your analysis in this EXACT format:

MATCHED_OPPORTUNITIES: [comma-separated list of opportunity numbers that match, or "NONE"]
CONFIDENCE: [high/medium/low]
REASONING: [Brief explanation of why these opportunities match or don't match]

Be thorough - consider semantic relationships, not just exact string matches.
For expired contracts, prioritize finding active renewal opportunities.
```

ENHANCEMENTS IN VERSION 5.0:
- Automatic calculation of days_until_renewal for every contract
- Renewal urgency classification (EXPIRED, CRITICAL, HIGH, MEDIUM, LOW)
- Detection of renewal contracts from titles ("renewal" in filename)
- CRM stage analysis: Lost = FAILED, Won = CONTRACT SIGNED, Other = ACTIVE ENGAGEMENT
- Active engagement flag to identify contracts being actively worked
- Urgent alerts for contracts without CRM tracking
- Enhanced output with visual indicators (emojis) and sorted by urgency
- Deduplication logic using seen_files set to prevent counting same contract twice
- Contract Expiration Date from CRM included in matching context
- Special logic for expired contracts: looks for ACTIVE opportunities with "renewal" keywords and 7% amount tolerance

Input Variables:
  - contract_info: Contract file name, products, amount, dates, status
  - opp_info: List of CRM opportunities with names, owners, products, amounts, stages, next steps, contract expiration dates

Output Format:
  - MATCHED_OPPORTUNITIES: List of opportunity indices (1-based) or "NONE"
  - CONFIDENCE: high/medium/low
  - REASONING: Explanation of matching logic

Example Input:
  CONTRACT INFORMATION:
  Contract File: Confluent_IBM-1.30.2025.docx
  Products: watsonx Orchestrate, watsonx.governance, watsonx.ai
  Amount: $250,000
  Start Date: 1/31/2024
  End Date: 1/31/2026
  Status: expired
  
  CRM OPPORTUNITIES:
  Opportunity 1:
  Name: Confluent watsonx as a Service Renewal
  Owner: Anand Das
  Products: watsonx
  Amount: $250,000
  Stage: Qualified
  Next Steps: sizing in progress
  Contract Expiration Date: 1/31/2026

Example Output:
  MATCHED_OPPORTUNITIES: 1
  CONFIDENCE: high
  REASONING: Expired contract (1/31/2026) matches CRM Contract Expiration Date (1/31/2026). "watsonx ESA" is semantically equivalent to "watsonx as a Service". Dollar amounts match exactly ($250K). Active renewal opportunity in Qualified stage with "sizing in progress" indicates ongoing engagement. Strong match on all criteria.

Fallback Behavior:
  - If LLM fails, system falls back to simple string matching
  - Fallback uses substring matching on product names
  - Fallback provides lower confidence scores

The Matching Agent returns enriched match objects containing:
  - Complete contract object with all structured fields (amount, products, dates)
  - Complete CRM opportunity details (owner, next_steps, stage, amount, contract_expiration_date)
  - Match confidence level (high/medium/low)
  - Match reasoning (LLM explanation)
  - Status and urgency metrics
  - Deduplication ensures each contract counted only once

PROMPT 5.1: Draft Email Generation (ENHANCED v6.0)
---------------------------------------------------
Location: action_agent.py, line 1266
Purpose: Generate professional executive outreach email with contract context, expansion opportunities, and previous signers, with enhanced quality controls for word repetition and CRM note paraphrasing
Model: meta-llama/llama-3-3-70b-instruct
Parameters:
  - max_new_tokens: 500
  - temperature: 0.2
  - decoding_method: greedy

Template:
```
Write a professional, executive-level outreach email from an IBM seller to {recipient_display} at {partner_name}.

RECIPIENT INFORMATION:
- Role: {recipient_role}
- Name: {recipient_name}
- Use name in greeting if provided, otherwise use role title
- NOTE: For Confluent, executives are HARD-CODED:
  - CPO: Shaun Clowes (pre-acquisition)
  - CTO: Stephen Deasy (pre-acquisition)
  - CEO: Jay Kreps (pre-acquisition)
  - CFO: Rohan Sivaram (pre-acquisition)

CONTRACT CONTEXT:
{contract_details}

CRM INFORMATION:
{crm_context}

URGENCY:
{urgency_context}

EXPANSION OPPORTUNITIES:
{expansion_analysis}

PREVIOUS SIGNERS:
{previous_signers}

ADDITIONAL CONTEXT:
- Risk Level: {risk_level}
- Partner Maturity: {maturity}
- Top Priority Action: {top_step}
- Why Contract Expired: {expiration_reason}

WRITING RULES — follow every one:
1. Output EXACTLY ONE email. No alternatives, no commentary, no markdown fences.
2. Open with 'Subject:' on the first line, blank line, then 'Hi {greeting},'.
3. Match this style closely: short, direct, conversational, and human — like a real seller follow-up, not a formal executive letter.
4. Keep it to 2 short paragraphs, roughly 90-140 words total.
5. In paragraph 1, say it was great connecting and ask whether sizing for the SPECIFIC renewal has been finalized. MUST mention the specific product(s) from CONTRACT FACTS above (e.g., 'watsonx renewal' or 'Cognos renewal') so it's clear which renewal you're discussing.
6. In paragraph 2, mention the contract has expired and that you want to help get it in quickly. If appropriate, mention helping avoid a 5% penalty or exception-related delay in a natural, non-legalistic way.
7. Ask if it would be helpful to schedule a call and invite questions.
8. Mention the CRM account owner only if it feels natural; do not make the email sound internal or operational.
9. Use the first name only in the greeting. Do not use full name or title in the greeting.
10. Do not sound stiff, overly polished, or generic. Avoid phrases like 'I hope this message finds you well' and avoid heavy executive tone.
11. CRITICAL: Do NOT repeat words in the same sentence or adjacent sentences (e.g., avoid 'forward...forward', 'renewal...renewal').
12. CRITICAL: Do NOT quote CRM notes verbatim. Paraphrase professionally and naturally. CRM notes are internal context only - translate them into executive-appropriate language.
13. Write naturally as if speaking to an executive peer. Avoid awkward phrasing or grammatically incorrect constructions.
14. Close with exactly:
    Regards,
    [Your Name]

STOP immediately after the signature. Output nothing else.
```

ENHANCEMENTS IN VERSION 6.0 (2026-04-20):
- CRITICAL: Prevents word repetition in same/adjacent sentences
- CRITICAL: Requires professional paraphrasing of CRM notes (no verbatim quotes)
- Ensures grammatically correct, natural executive-level language
- Requires specific product mention (e.g., "watsonx renewal" not "the renewal")
- Conversational, human tone (not stiff or overly formal)
- Hard-coded Confluent executives (Shaun Clowes, Stephen Deasy, Jay Kreps, Rohan Sivaram)
- All executives marked as "pre-acquisition" for context
- Expansion opportunity context included in email
- Previous contract signers referenced for continuity
- Root cause analysis of why contract expired
- Enhanced context for more targeted outreach
- Contract Expiration Date awareness for better timing context

Input Variables:
  - recipient_display: Name or role of recipient (e.g., "Shaun Clowes" or "CPO")
  - recipient_role: Executive role (CPO, CTO, CEO, CFO)
  - recipient_name: Actual name if available, otherwise "Not available - use role title"
  - partner_name: Company name (e.g., "Confluent")
  - contract_details: Specific contract information (product, value, dates, status)
  - crm_context: CRM opportunity details (owner, next steps, stage, contract expiration date)
  - urgency_context: Urgency explanation (days expired, risk factors)
  - expansion_analysis: Expansion opportunity details if identified
  - previous_signers: Names of previous contract signers for continuity
  - risk_level: High/Medium/Low
  - maturity: Partner maturity level (Strategic Partner, Engaged Prospect, etc.)
  - top_step: Top priority action from recommendations
  - expiration_reason: Root cause analysis of why contract expired

Output Format:
  - Complete email with subject line
  - Professional greeting (uses name if available)
  - 2-3 paragraph body
  - Clear call to action
  - Professional closing: "Best regards, [Your Name], IBM Seller"

Example Input:
  recipient_display: Shaun Clowes
  recipient_role: CPO
  recipient_name: Shaun Clowes
  partner_name: Confluent
  contract_details: watsonx ESA contract ($250,000.00) expired 72 days ago on 1/31/2026
  crm_context: Anand Das owns renewal opportunity, next steps: "sizing in progress", Contract Expiration Date: 1/31/2026
  urgency_context: Contract expired 72 days ago, $250K at risk, customer actively sizing
  expansion_analysis: Customer actively sizing - potential for expansion
  previous_signers: John Smith, Jane Doe

  expiration_reason: Timing gap - active discussions but contract lapsed

  Given the strategic value of this $250,000 partnership and your ongoing evaluation, I'd like to schedule a brief call this week to ensure we're aligned on your requirements and timeline. Our team is ready to support your sizing process and expedite the renewal to maintain continuity. I also see potential for expansion opportunities we could explore together.

  Best regards,
  [Your Name]

PROMPT 5.2: Email Editing/Regeneration (Interactive Workflow)
--------------------------------------------------------------
Location: workflow_in_steps.ipynb, lines 634-720
Purpose: Edit and refine draft emails based on user feedback in interactive notebook workflow
Model: meta-llama/llama-3-3-70b-instruct
Parameters:
  - max_new_tokens: 600
  - temperature: 0.3
  - decoding_method: sample
  - stop_sequences: ["```", "\n\n\n\n"]

Template:
```
You are a professional email editor. Edit the following email based on the user's request.

ORIGINAL EMAIL:
{original_email}

USER REQUEST: {edit_request}

INSTRUCTIONS:
- Generate ONLY ONE complete email (no multiple versions or alternatives)
- Start directly with 'Subject:' - no preamble or introduction
- Do NOT repeat phrases or content
- End cleanly after the signature line 'IBM Seller'
- Do NOT add explanations, meta-commentary, or markdown formatting
- Maintain professional business tone

EDITED EMAIL:
```

Input Variables:
  - original_email: The draft email generated by Action Agent
  - edit_request: User's specific editing instructions (e.g., "make it more urgent", "add a deadline")

Output Format:
  - Single complete email starting with "Subject:"
  - No markdown code blocks or formatting
  - Ends at "IBM Seller" signature
  - No meta-commentary or explanations

Post-Processing Function (clean_email_output):
1. Remove markdown code blocks (```)
2. Extract content starting from "Subject:"
3. Cut at first "IBM Seller" signature
4. Remove duplicate consecutive lines
5. Reduce excessive blank lines (max 2 consecutive)
6. Trim whitespace

Example Input:
  original_email: "Subject: Contract Renewal\n\nDear CPO,\n\nI am writing regarding...\n\nBest regards,\nJohn Doe\nIBM Seller"
  edit_request: "Make it more urgent and add a deadline of April 15th"

Example Output:
  Subject: URGENT: Contract Renewal Required by April 15th

  Dear CPO,

  I am writing to urgently address our contract renewal, which requires your immediate attention. To ensure continuity of service, we need your response by April 15th.

  [rest of email content]

  Best regards,
  John Doe
  IBM Seller

Common Edit Requests:
- "Make it more urgent" → Add urgency language and time pressure
- "Add a deadline of [date]" → Include specific deadline in subject and body
- "Make it shorter" → Condense to key points only
- "Make it more friendly" → Soften tone while maintaining professionalism
- "Add bullet points" → Format key items as bulleted list

CRITICAL IMPLEMENTATION NOTES:
- Stop sequences prevent markdown artifacts and excessive whitespace
- Post-processing ensures clean output even if LLM generates extra content
- Regex-based cleaning removes any preamble before "Subject:"
- Signature detection cuts at first "IBM Seller" to prevent repetition
- Duplicate line removal prevents repeated phrases
- Import `re` module required for post-processing

Troubleshooting:
- If output has "```" markers → Check stop_sequences parameter
- If multiple emails generated → Emphasize "ONLY ONE" in prompt + post-processing extracts first
- If text after signature → Post-processing cuts at "IBM Seller"
- If repeated phrases → Duplicate line removal in post-processing
- If preamble text → Regex extraction starts from "Subject:"

TROUBLESHOOTING

Common Issues and Solutions:

Issue: LLM returns explanations instead of just the output
Solution: Add "Return ONLY [desired output], no additional text" to prompt

Issue: Output format is inconsistent
Solution: Provide explicit format template with examples

Issue: LLM ignores specific instructions
Solution: Emphasize critical requirements with "IMPORTANT:", "MUST:", or "EXACTLY:"

Issue: Output is too verbose
Solution: Add length constraints (e.g., "Keep it concise (under 200 words)")

Issue: Tone is inappropriate
Solution: Specify exact tone (e.g., "Use executive tone appropriate for CPO level")

Issue: LLM generates multiple versions
Solution: Add "Do NOT include multiple versions" + post-processing to extract first only

Issue: Missing specific data (amount, products, dates)
Solution: Use regex extraction for structured data instead of relying on LLM

Issue: Generic recipients instead of names
Solution: Hard-code known executives (like Confluent team) in code, not prompts

Issue: Inconsistent field names in output
Solution: Use consistent naming across all agents (e.g., "next_steps" not "agent_next_steps")

Issue: Wrong dates extracted from contracts
Solution: Use regex to extract from Coverage Period field, don't calculate from start_date + term_length

Issue: Wrong products extracted
Solution: Look at IBM Cloud Subscription table's Product Description column, use specific rules for watsonx and Cognos

Issue: Duplicate contracts counted
Solution: Implement deduplication logic using seen_files set in matching_agent.py

Issue: Missing expired contracts
Solution: Capture ALL expired contracts (days_to_end < 0), not just last 90 days

Issue: Expired contracts not matching to renewal opportunities
Solution: Add Contract Expiration Date to CRM context, use special matching logic for expired contracts

PERFORMANCE OPTIMIZATION

Tips for faster, more reliable prompts:

1. Cache Results: Store extracted data to avoid re-processing (contracts_cache.json)
2. Reduce Token Count: Use concise prompts without unnecessary words
3. Greedy Decoding: Use for structured outputs (metadata, JSON)
4. Sample Decoding: Use for creative outputs (emails, summaries)
5. Lower Temperature: Use 0.1-0.3 for factual extraction
6. Higher Temperature: Use 0.5-0.7 for creative writing
7. Batch Processing: Process multiple items in one call when possible
8. Rule-Based First: Use code for simple tasks (date extraction), LLM for complex (synthesis)
9. Hard-Code Known Data: Don't waste tokens on data you already know
10. Regex for Patterns: Extract structured data with regex, not LLM
